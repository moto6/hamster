# 테스트 규칙

## 환경
- 통합 테스트는 **Testcontainers**를 쓴다. 이미지 태그는 `compose.yaml`과 동일하게 (`postgres:17-alpine`).
- **H2 금지.** 락 동작이 실제 PostgreSQL과 달라 동시성 테스트가 무의미해진다.
- 데이터소스 연결은 `@ServiceConnection`으로. 프로퍼티를 수동으로 넣지 않는다.
- 테스트는 로컬 개발 DB가 아니라 별도 컨테이너에서 돈다.

## 동시성 테스트 (필수)
경합이 발생하는 모든 자원에 대해 작성한다.
- `ExecutorService` + `CountDownLatch`로 N개 스레드를 동시에 출발시킨다.
- 최종 상태를 **정확한 값으로** 검증한다. "0 이상" 같은 느슨한 단언은 안 된다.
- 검증 대상: 재고 수량, 성공한 주문 수, 쿠폰 사용 횟수.

## 작성 규칙
- 테스트명은 한국어 백틱: ``fun `재고보다 많은 수량을 주문하면 실패한다`()``
- given / when / then 주석으로 구조를 드러낸다.
- 통합 테스트에서 리포지토리를 목킹하지 않는다. 목킹은 PG 시뮬레이터에만.
- 완료를 보고하기 전에 `./gradlew test`를 **실제로 실행**한다. 통과를 가정하지 않는다.
- 불필요한 테스트는 작성하지 않는다 요구사항과 관련이 없거나, 의미가 없는 테스트는 추가하지 않는다
- 통과하기 위해 낙관적이고 의미없는 테스트를 추가하지 않는다. 테스트에 실패하는 경우 테스트 실패한다고 보고하고 실행을 종료하고 사용자에게 보고해라
