## 2. 핵심 관례

### 라우트 + 메뉴 + 탭 = 단일 소스
`app/gnb/navigation.config.tsx` 의 `GNB_NAV_ITEMS` 한 곳만 고치면 세 곳에 동시 반영된다:
- **라우트**: `AppRoutes.tsx`(및 `main.tsx`)가 `GNB_NAV_ITEMS.map(... <Route>)` 로 생성.
- **GNB 메뉴**: `Gnb.tsx` 가 `GNB_NAV_GROUPS`(카테고리)별로 항목을 묶어 렌더.
- **MDI 탭**: `TabStore` 가 URL ↔ 항목을 매칭해 탭을 연다.

```ts
{
  label: '연체 관리',
  path: '/library-admin/overdue',
  element: <OverdueManagementPage/>,
  category: "LIBRARY-ADMIN",   // 그룹핑 키 (GNB_NAV_GROUPS 와 매칭)
  icon: ListChecks,            // 선택 (lucide-react)
  hidden: true,                // 메뉴엔 숨기되 라우트/탭은 동작
}
```
- `category`: `"LIBRARY-ADMIN" | "LIBRARY-USER" | "PLACE" | "JIRA" | "TEST" | "SYSTEM"` 등.
- 그룹의 `hidden`(`GNB_NAV_GROUPS`) 또는 항목의 `hidden` → 메뉴 비노출.
- **권한 게이팅(RBAC)**: 메뉴 노출은 UX 일 뿐 실제 보안은 백엔드가 강제한다. 역할별 메뉴는 카테고리/그룹 노출로 다루고, 페이지 진입 보호는 `ProtectedRoute` + 백엔드 인가로 이중 확보한다(아래).

### 인증 셸 (`main.tsx`)
```
<BrowserRouter>
  <Route element={<PublicRoute/>}>      → /login
  <Route element={<ProtectedRoute/>}>   → <AdminLayout/> 아래 모든 업무 라우트
  <Route path="*" → /login>
```
- `PublicRoute`: 이미 인증된 사용자를 업무 화면으로 보냄.
- `ProtectedRoute`: 미인증 시 `/login` 으로 리다이렉트(원 경로 보존). 실제 보안 판정은 호출이 백엔드에서 401/403 으로 강제된다.

### API 호출 (`core/http/libraryClient.ts`)
두 개의 axios 인스턴스를 쓴다:
- `libraryApiClient` — 업무 API 용. **요청 인터셉터**가 메모리의 access token 을 `Authorization: Bearer` 로 첨부. **응답 인터셉터**가 401 이면 refresh 후 원본 요청을 **1회만** 재시도.
- `authApiClient` — 인증 API(`/api/v0/auth/*`) 전용. refresh 쿠키 전송을 위해 `withCredentials: true`.

토큰 전략(보안 이음새):
- **access token 은 메모리에만** 보관(`setAccessToken`/`getAccessToken`) → localStorage 미사용으로 XSS 토큰 탈취 표면 축소.
- **refresh token 은 HttpOnly 쿠키**(백엔드 관리, JS 접근 불가).
- **single-flight refresh**: 동시 다발 401 이 나도 `inflightRefresh` Promise 를 공유해 `/api/v0/auth/refresh` 를 한 번만 호출한다.
- origin 은 `VITE_API_URL`(개발=교차 origin) / 빈 값(배포=상대경로 → nginx same-origin 프록시).

```ts
import {libraryApiClient} from "@/core/http/libraryClient.ts";
const {data} = await libraryApiClient.get<Page>('/api/v0/admin/library/books');
```

### 데이터 훅 — All-in-One Hook
페이지마다 `use{Domain}.ts` 하나에 인터페이스·fetch·상태(`useState`/`useEffect`)를 모은다. 화면(`*Page.tsx`)은 그 훅만 호출한다. 도메인 공통 인터페이스는 `libraryTypes.ts` 같은 공통 파일에 선언해 참조한다(상세: [3_구현_프론트_전략.md](3_구현_프론트_전략.md)).

## 3. MDI 탭 시스템 (크롬 스타일)

목적: 여러 화면을 탭으로 열고 **전환해도 상태(폼 입력·스크롤)를 유지**하며 재렌더링을 최소화한다.

- `TabContainer` 가 **열린 모든 탭의 element 를 동시에 마운트**해 두고, active 가 아닌 탭은 `invisible/opacity-0/pointer-events-none` 로 숨긴다(언마운트하지 않으므로 상태가 보존된다 = keep-alive).
- `TabStore`(TabProvider)가 진실의 원천:
  - **lazy init**: 최초 URL 로 첫 탭을 구성.
  - `openTab/closeTab/setActiveTab` 가 상태 변경과 `navigate()` 를 함께 처리.
  - 브라우저 뒤로/앞으로가기(`location.pathname`)와 탭 상태를 동기화(없던 탭이면 추가).
  - 탭 id = `path`. element 는 `GNB_NAV_ITEMS` 에서 가져온다.
- `useTab()`(`tabs.ts`)으로 어디서든 탭 상태/조작 접근.

> 즉 탭에 띄울 화면은 별도 등록이 필요 없다 — `GNB_NAV_ITEMS` 에 있으면 탭이 그 `element` 를 그대로 keep-alive 로 렌더한다.

## 4. 새 페이지 추가 (3스텝)

1. **페이지 + 훅 작성** — `src/pages/{category}/My DomainPage.tsx` 와 `useMyDomain.ts`.
   기존 `pages/library/*` 또는 `pages/place/*` 패턴 복제(서버 연동은 `libraryApiClient`).
2. **네비게이션 등록** — `app/gnb/navigation.config.tsx` 의 `GNB_NAV_ITEMS` 에 항목 1개 추가(위 예시 형태). 새 그룹이면 `GNB_NAV_GROUPS` 에 카테고리도 추가.
3. 끝. **라우트·메뉴·MDI 탭·뒤로가기 동기화가 자동**으로 따라온다.

(서버 API 가 새로 필요하면 훅 안에서 `libraryApiClient` 호출만 추가하면 된다 — 별도 api 레이어 강제 없음.)

## 5. 스타일 (Tailwind v4 · Radix)

- 디자인 토큰은 `index.css` 의 `@theme`(색/라운드/폰트). **수정 자제** — `border-border`/`bg-card`/`bg-background` 등 시맨틱 토큰을 쓴다(상세 규칙: [2_설계_프론트_구조설계.md](2_설계_프론트_구조설계.md)).
- UI 프리미티브는 `components/library/*`(Radix + `class-variance-authority` + `cn`). 아이콘은 `lucide-react`(메뉴 `strokeWidth={1.5}`, 본문 `size 18~20`).
- 상태관리 라이브러리(zustand 등) **미사용** — Context(`TabContext`) + 로컬 상태로 충분히 처리.

## 6. 실행 / 빌드

```bash
cd hamster-front
npm install
npm run dev      # vite, http://localhost:5173 (백엔드 :8080 필요)
npm run build    # tsc -b 타입체크 + vite 프로덕션 번들 (→ dist/)
npm run lint
```

배포는 `dist/` 를 nginx 이미지로 빌드(`Dockerfile`) → `infra/docker-compose.yml`. nginx 가 `/api/` 를 `hamster-back:8080` 으로 프록시해 **same-origin** 으로 동작(인증 refresh 쿠키가 `path=/api/v0/auth` HttpOnly 라 same-origin 프록시가 필수다).
