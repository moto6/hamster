# 추가 개발 가이드

hamster 에 기능을 얹고, 실서비스로 끌어올리기 위한 안내.
구조/원칙의 자세한 설명은 [아키텍처-코드.md](아키텍처-코드.md) 를 함께 본다.

---

## 1. 새 도메인 기능 추가 (백엔드 — 수직 슬라이스)

도서(`book`) 슬라이스가 레퍼런스다. 한 기능은 **코어(도메인+포트+서비스) → 앱(컨트롤러+어댑터) → 마이그레이션** 순서로 한 줄기로 만든다. 예) library-core 에 `widget` 추가:

1. **도메인** — `library-core/.../widget/domain/Widget.kt`
   순수 Kotlin 모델 + 불변식. 식별자는 `foundation` 의 `identity/*Id` 패턴 사용(또는 신규 추가).
   ```kotlin
   class Widget(val id: WidgetId, val name: String) { /* 비즈니스 규칙 */ }
   ```
2. **In 포트(UseCase)** — `library-core/.../widget/app/contract/WidgetUseCase.kt`
   ```kotlin
   interface WidgetUseCase {
       suspend fun register(command: WidgetRegisterCommand): WidgetResult
       suspend fun list(query: WidgetSearchQuery): CursorPage<WidgetResult>
   }
   ```
   Command/Query/Result 는 `app/contract/payload` 에 둔다.
3. **Out 포트** — `library-core/.../widget/app/contract/WidgetOutPort.kt`
   ```kotlin
   interface WidgetOutPort { suspend fun save(widget: Widget) }
   ```
4. **서비스** — `library-core/.../widget/app/service/WidgetService.kt` (`@Service`)
   In 포트 구현. 도메인 조립 후 Out 포트 호출. `AdminBookService` 를 그대로 복제.
5. **R2DBC 레코드 + 리포지토리** — `hamster-api/.../widget/infra/persistence/`
   ```kotlin
   @Table("widget") data class WidgetRecord(@Id val id: Long? = null, val name: String) {
       companion object { fun from(w: Widget) = WidgetRecord(name = w.name) }
   }
   interface WidgetRepository : CoroutineCrudRepository<WidgetRecord, Long>
   ```
6. **어댑터** — `hamster-api/.../widget/app/WidgetPersistenceAdapter.kt` (`@Component`)
   Out 포트를 R2DBC 로 구현(`BookPersistenceAdapter` 복제).
7. **컨트롤러** — `hamster-api/.../widget/api/WidgetController.kt`
   ```kotlin
   @RestController
   @RequestMapping("/api/v0/admin/library/widgets")
   class WidgetController(private val useCase: WidgetUseCase) {
       @GetMapping
       suspend fun list(params: WidgetSearchQuery, @AuthPrincipal authInfo: AuthInfo)
           : CursorPage<WidgetResult> = useCase.list(params)   // 필요 시 인가 검사
   }
   ```
   요청/응답 DTO 는 `api/dto` 에 두고 `toCommand()`/`fromResult()` 로 변환.
8. **마이그레이션** — `hamster-api/src/main/resources/db/migration/V{n}__add_widget.sql`
   기존 파일은 수정하지 말고 **새 버전 파일**로만 추가(부팅 시 `FlywayConfig` 가 적용).
9. **DI** — 어노테이션(`@Service`/`@Component`)이면 컴포넌트 스캔으로 자동 연결된다. 명시 등록이 필요하면 `config/ApplicationBeanConfig.kt` 패턴 참고.

> 모듈 경계 주의: 컨트롤러/어댑터/레코드는 `hamster-api`, 도메인/포트/서비스는 `library-core`(또는 `place-core`)에 둔다. **코어가 `hamster-api` 를 import 하면 안 된다**(의존 방향 역전 금지).

핸들러는 항상 `suspend fun`, 리포지토리는 `CoroutineCrudRepository`, 목록은 `CursorPage<T>` 로 통일한다.

## 2. place-core(공간 예약) 확장

도서와 동일 패턴. 현재 `hamster-api/.../place/api`(컨트롤러·DTO: 건물/방/자원/예약/대시보드)가 진입점이고, 도메인·포트·서비스를 `place-core` 로 끌어올리며 R2DBC 어댑터를 붙인다.

## 6. 실서비스 준비 체크리스트 (있는 것 vs TODO)

기능 골격에 집중한 상태다. 정식 서비스로 올리려면 아래를 채운다(우선순위 순).

| # | 항목 | 지금 상태 | 해야 할 일 |
|---|------|-----------|-----------|
| 1 | **DB 마이그레이션** | ✅ Flyway 도입(`db/migration`, `FlywayConfig`) | 운영 적용 정책(롤백 전략, `baseline`), R2DBC/JDBC 커넥션 일원 관리 |
| 2 | **인증 완성** | 발급(`/tokens`)+WebFilter 검증만 구현 | `login`/`callback`/`refresh`/`logout`/`me` 구현, refresh 회전·재사용 탐지, 실 SSO 연동 |
| 3 | **모니터링·알림** | 없음 | `actuator` + Prometheus/Grafana, 에러 추적, 장애 알림 |
| 4 | **CI/CD** | 수동(`./gradlew`, docker compose) | GitHub Actions 등 test→build→배포 자동화, 품질 게이트 |
| 5 | **테스트 커버리지** | 일부(foundation 단위 등) | 도메인/통합/슬라이스 테스트, 프론트 컴포넌트·E2E |
| 6 | **인프라 견고성** | 단일 호스트 compose(헬스체크 일부) | 이중화(HA), 무중단 배포, 오토힐 |
| 7 | **보안 점검** | 기본 | 의존성 취약점 스캔(SCA), 시크릿 매니저, HTTPS/TLS, (SSO 시) JWKS 서명검증, 쿠키 `Secure` |
| 8 | **로깅/감사** | 콘솔 + `AuthHistory` 발급이력 | 구조화 로그 수집, 주요 변경 audit |
| 9 | **부하/성능** | 미검증 | 부하 테스트, R2DBC 풀·인덱스 튜닝, 커서 페이지네이션 활용 |

> 1~2 가 "사고를 막는" 핵심이고(특히 인증은 프론트·인프라가 이미 계약을 바라봄), 나머지는 사용량이 늘며 단계적으로.

## 7. 의도적으로 비워둔 것 / 주의

- **일부 서비스가 Mock 반환**: `AdminBookService.listSkus()` 등은 하드코딩 샘플을 반환(`update`/`delete` 는 `TODO`). 실제 R2DBC 조회로 교체하는 자리다.
- **인증 더미 시크릿**: 레포의 `custom.jwt.secret` 과 compose 의 `AUTH_JWT_SECRET` 기본값은 개발 전용. 운영은 강한 시크릿/실 IDP 로 교체.
- **시크릿 커밋 금지**: `infra/.env`, JWT 시크릿, IDP 클라이언트 시크릿, DB 비밀번호는 환경변수/시크릿 매니저로만.
- **모듈 경계 유지**: 코어(`library-core`/`place-core`/`iam-core`)는 `hamster-api` 에 의존하지 않는다.
