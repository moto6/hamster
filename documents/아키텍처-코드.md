# 아키텍처 (백엔드 코드)

> 대상: `hamster-back` (Kotlin 2.2 · Spring Boot 4.1 · Java 21 · **WebFlux + R2DBC + Coroutines** · Flyway)
> 핵심 원칙: **도메인/유스케이스는 코어 모듈에, 인프라(웹·영속성·인증)는 어댑터로** 분리하고,
> 인증/인가는 공통 골격(`auth`)이 책임지며 도메인은 얇은 수직 슬라이스로 추가한다.

---

## 1. 멀티모듈 구조

`hamster-back` 은 단일 Gradle 멀티모듈 프로젝트다 (`settings.gradle`).

```
hamster-back/
├── foundation/      # 공유 커널: 값 타입·식별자·페이지네이션 (스프링 의존 X)
├── iam-core/        # 계정/사용자 도메인 골격 (Admin, User)
├── library-core/    # 도서관 도메인 + 유스케이스 계약(포트) + 서비스
├── place-core/      # 회의실(공간) 예약 도메인 (확장 예정)
├── hamster-api/     # ★ 실행 가능한 Spring Boot 앱: 컨트롤러 · 어댑터 · 설정 · 인증
└── hamster-batch/   # 배치 잡 (랭킹 집계·대용량 적재 등, 별도 실행)
```

| 모듈 | 책임 | 스프링 의존 |
|------|------|------------|
| `foundation` | `BookSkuId`/`UserId` 등 식별자, `Isbn`/`EmailAddress` 값 객체, `CursorPage`, `IdGenerator`(UUIDv7) | 없음(순수 Kotlin) |
| `iam-core` | `Admin`/`User` 등 계정 도메인 모델 | 최소 |
| `library-core` | 도메인 모델(`BookSku`·`BookReservation`·`LoanOverdue`…) + **유스케이스 계약(포트)** + **서비스 구현** | 일부(`@Service`) |
| `place-core` | 공간 예약 도메인(건물/방/자원/예약/대시보드) | 일부 |
| `hamster-api` | REST 컨트롤러(`api/`), R2DBC 영속성 어댑터(`infra/persistence`), 인증(`auth/`), 전역 설정(`config/`) | 전부(WebFlux 앱) |
| `hamster-batch` | 스케줄/배치 진입점 | 배치 |

패키지 루트는 모듈마다 다르다: 코어는 `com.librarycore`/`com.iamcore`, 앱은 `com.hamsterapi`, 공유 커널은 최상위(`identity`/`name`/`collections`/`id`).

> **의존 방향**: `hamster-api` → (`library-core`/`place-core`/`iam-core`) → `foundation`.
> 코어는 앱(웹/DB)을 모른다. 앱이 코어의 **포트(인터페이스)** 를 구현(어댑터)해 주입한다.

## 2. 헥사고날(포트/어댑터) 계층

도서 슬라이스를 예로, 한 요청이 흐르는 길:

```
요청
 → [JwtAuthWebFilter] 토큰 검증 → exchange 에 AuthInfo 적재
 → [Controller]  com.hamsterapi.book.api.AdminBookController   (@AuthPrincipal 로 AuthInfo 주입)
 → [UseCase 포트] com.librarycore.book.app.cotract.AdminBookSkuUseCase   (인터페이스, library-core)
 → [Service]      com.librarycore.book.app.service.AdminBookService      (@Service, library-core)
 → [Out 포트]     com.librarycore.book.app.cotract.BookOutPort           (인터페이스, library-core)
 → [Adapter]      com.hamsterapi.book.app.BookPersistenceAdapter         (@Component, hamster-api)
 → [Repository]   com.hamsterapi.book.infra.persistence.BookSkuMasterRepository (CoroutineCrudRepository)
 → R2DBC → PostgreSQL
```

| 자리 | 위치(모듈) | 책임 |
|------|-----------|------|
| **In 포트(UseCase)** | `library-core/.../app/cotract`(또는 `contract`) | 컨트롤러가 호출하는 진입 계약. 예: `AdminBookSkuUseCase`, `SearchBookUseCase`, `LoanUseCase` |
| **Service** | `library-core/.../app/service` | In 포트 구현. 도메인 모델을 조립하고 Out 포트를 호출. 예: `AdminBookService` |
| **Out 포트** | `library-core/.../app/cotract` | 영속성/외부 연동 계약. 예: `BookOutPort`, `ReservationOutPort`, `LoanPersistenceOutPort` |
| **Domain** | `library-core/.../domain` | 비즈니스 불변식. 예: `BookSku.addInventories()`, `BookInventoryStatus`, `LoanStatus` |
| **payload** | `app/cotract/payload`, `app/contract/payload` | Command/Query/Result DTO (계층 간 전달용) |
| **Controller** | `hamster-api/.../api` | HTTP 매핑 + 요청/응답 DTO 변환. 인가 검사. |
| **api/dto** | `hamster-api/.../api/dto` | HTTP 요청/응답 모델(`*Request`/`*Response`), `toCommand()`/`fromResult()` 변환 |
| **Adapter** | `hamster-api/.../app` 또는 `infra/persistence` | Out 포트의 R2DBC 구현 |
| **Record/Repository** | `hamster-api/.../infra/persistence` | `@Table` R2DBC 레코드 + `CoroutineCrudRepository` |

> **이음새(seam)**: 서비스는 `BookOutPort`(인터페이스)에만 의존한다. R2DBC를 Elasticsearch/캐시/읽기복제본으로 바꿔도 `library-core` 의 도메인·서비스는 무손상이다. (요구사항의 "인프라에 의존적이지 않은 코드: RDB 전문검색 → ES 로 갈아끼우기 쉽게"가 여기서 구현된다.)

### 의존성 주입
대부분 어노테이션 기반이다. 서비스는 `@Service`, 어댑터는 `@Component` 로 선언하고 생성자 주입으로 포트를 연결한다. (명시적 `@Bean` 등록은 `config/ApplicationBeanConfig.kt` 에 주석으로 남아 있다 — 어노테이션 스캔으로 충분하면 그쪽이 단일 진실이다.)

## 3. 리액티브 실행 모델 (WebFlux · R2DBC · Coroutines)

- **컨트롤러 핸들러는 `suspend fun`** 이다. 블로킹 스레드 풀이 아니라 Reactor/코루틴 위에서 동작한다.
  ```kotlin
  @GetMapping
  suspend fun getSkus(params: BookSkuSearchQuery): CursorPage<BookSkuResult> =
      bookSkuUseCase.listSkus(params)
  ```
- **영속성은 R2DBC** `CoroutineCrudRepository` 다. JPA(`@Entity`)가 아니라 Spring Data Relational `@Table` 레코드 + `suspend save/find` 를 쓴다.
  ```kotlin
  @Table("book_sku_master")
  data class BookSkuMasterRecord(@Id val id: Long? = null, val isbn: String, ...)

  interface BookSkuMasterRepository : CoroutineCrudRepository<BookSkuMasterRecord, Long>
  ```
- **WebFilter 경계는 Reactor 타입**(`Mono<Void>`)이지만 내부는 `mono { ... }` 코루틴 빌더로 작성한다(`JwtAuthWebFilter`).
- **페이지네이션은 커서 기반**(`collections.CursorPage`): `content` + `currentCursor` + `hasNext`. offset 페이지네이션의 깊은 페이지 성능 문제를 피하는 이음새다.

> 즉, "요청 스레드를 점유하지 않는" Non-Blocking 스택이다(요구사항: Spring Boot 4 + R2DBC/WebFlux/Coroutines). 다운스트림(DB·외부 API)도 리액티브 드라이버를 써야 이점이 유지된다.

## 4. 인증 / 인가 (`com.hamsterapi.auth`)

> 현재 코드에 **구현된 것**과 **설계로 자리 잡은(추가 진행 중인) 것**을 구분해 적는다.

### 4.1 패키지 골격
```
auth/
├── api/            AuthController (+ api/dto: JwtIssueRequest/Response)
├── app/            포트: AuthTokenPort · AuthHistoryOutPort · AuthPrincipal(어노테이션) · payload(AuthInfo, IssueTokenCommand)
├── iam/domain/     AdminRoles · AuthType · AccountStatus
└── infra/
    ├── jwt/         JwtAuthAdaptor(AuthTokenPort 구현) · JwtAuthWebFilter · AuthPrincipalArgumentResolver · AuthContextKeys
    └── persistance/ AuthHistory* (발급 이력) · BlockedToken* (폐기 토큰)
```

### 4.2 토큰 발급/검증 (구현됨)
- **자체 발급 JWT(access)** — HS256(`Keys.hmacShaKeyFor`), 클레임 `usr`/`eml`/`dnm` + `jti`(토큰 식별자) + `iat`/`nbf`/`exp`. 시크릿/만료는 `custom.jwt.secret`·`custom.jwt.expiration` 로 주입.
- 발급 진입점: `POST /api/v0/auth/tokens` → `AuthTokenPort.issue()` → `Authorization: Bearer <jwt>` 헤더 + 본문으로 반환.
- 발급 시 `AuthHistoryOutPort.saveHistory(jti, userId, token)` 로 **발급 이력**을 남긴다(감사/추적·재사용 탐지의 토대).
- 검증: `AuthTokenPort.verify(token)` → 서명/만료 검증 후 `AuthInfo` 로 매핑.

### 4.3 요청 인증 파이프라인 (구현됨)
1. `JwtAuthWebFilter`(WebFilter) 가 `Authorization: Bearer` 를 추출 → `verify()` → `ServerWebExchange` attribute(`AuthContextKeys.AUTH_INFO`)에 `AuthInfo` 적재. 검증 실패는 로깅만 하고 통과(보호 강제는 인가 단계에서).
2. 컨트롤러는 `@AuthPrincipal authInfo: AuthInfo` 로 주입받는다. `AuthPrincipalArgumentResolver` 가 attribute 에서 꺼내 바인딩하며, 없으면 401 의미의 에러.

`AuthInfo(username, userId, email, displayName, tokenId)` 가 인증된 호출자를 표현한다.

### 4.4 IDP 포트/어댑터 (설계 이음새)
인증 컨트롤러/토큰 서비스는 외부 신원 제공자(IDP)를 직접 알지 않도록 **포트 뒤로 분리**한다. `AuthTokenPort` 가 발급/검증의 포트이고, IDP(외부 신원 확인) 역시 같은 방식으로 어댑터화한다:
- **Mock IDP**(개발용) ↔ **SSO/OIDC**(운영) 를 환경값(`AUTH_IDP=mock|sso`)으로 전환.
- 외부 SSO 설정은 `SSO_ISSUER`/`SSO_CLIENT_ID`/`SSO_CLIENT_SECRET`/`SSO_REDIRECT_URI` 환경변수로 주입(`infra/docker-compose.yml` 참고).

> 교체 절차: ① IDP 어댑터 추가 → ② 인증 설정의 분기(또는 `@Profile`/조건부 빈)에 등록 → ③ `AUTH_IDP` 전환. 코어/서비스는 무손상.

### 4.5 Refresh 토큰 — 회전 + 재사용 탐지 (설계)
프론트(`core/http/libraryClient.ts`)·nginx(`/api/v0/auth` HttpOnly 쿠키 프록시)·compose 환경값이 이미 다음 모델을 전제로 한다:
- **access(JWT)는 stateless**, **refresh 는 HttpOnly 쿠키** + 서버 저장(해시) → XSS 로 access 토큰을 훔쳐도 수명이 짧고, refresh 는 JS 가 못 읽는다.
- **회전(rotation)**: `/refresh` 마다 새 access + 새 refresh 발급.
- **재사용 탐지**: 이미 폐기된 refresh 가 다시 들어오면 해당 토큰 체인을 무효화. `auth/infra/persistance/BlockedToken*` 와 `AuthHistory*`(jti 이력)가 그 토대다.

> 현재 백엔드에 구현된 엔드포인트는 토큰 발급(`/tokens`)과 WebFilter 검증이다. `login`/`callback`/`refresh`/`logout`/`me`(모두 `/api/v0/auth/*`)는 위 모델을 따라 채워 넣는 자리이며, 프론트/인프라는 이미 그 계약을 바라본다.

### 4.6 RBAC
- 역할: `USER` · `MANAGER` · `SUPER_ADMIN` (`auth/iam/domain/AdminRoles.kt`). `SUPER_ADMIN` 전권, `MANAGER` 스코프 관리(도서/공간 운영), `USER` 일반.
- 인가는 컨트롤러/서비스에서 호출자(`AuthInfo`)의 역할을 검사해 강제한다. 권한 미보유는 403.
- 신규 스코프 권한은 `AdminRoles` 에 값 추가 → 해당 핸들러에서 검사 한 줄 추가(예: `adminAuthorization.verify(authInfo, MANAGER)`).

> **2단 방어**: 프론트의 메뉴/라우트 게이팅은 UX 일 뿐, 실제 보안은 백엔드가 강제한다.

## 5. DB / 마이그레이션

- DBMS: **PostgreSQL**, DB명 `library`(로컬/compose 동일).
- **런타임은 R2DBC**(reactive), **마이그레이션은 Flyway(JDBC)** — 둘은 별개 커넥션이다.
  - R2DBC: `spring.r2dbc.*`
  - Flyway: `custom.flyway.*`(`url`/`user`/`password`/`path`/`baseline-on-migrate`) → `FlywayConfig` 가 부팅 시 `migrate()`.
- 마이그레이션 파일: `hamster-api/src/main/resources/db/migration/V1__create_essentials.sql`
  주요 테이블: `user_master` · `book_sku_master` · `book_inventory_detail` · `loan_master` · `loan_detail` · `reservation` · `loan_overdue` · `book_rating`.
  `book_sku_master.available_copies` 는 조회 성능용 **역정규화 컬럼**, `book_rating` 은 `(book_sku_id, user_id)` UNIQUE 로 중복 평점 방지.

스키마 변경은 새 `V{n}__*.sql` 을 추가한다(수정/삭제 금지, 이력으로만).

## 6. 환경 설정 / 시크릿

- 기본은 `application.yml`, 프로파일/배포는 환경변수 override(compose 의 `SPRING_R2DBC_*`, `SPRING_FLYWAY_*`, `AUTH_*`, `CORS_ALLOWED_ORIGINS`, `FRONTEND_BASE_URL`).
- **시크릿(`AUTH_JWT_SECRET`, `SSO_CLIENT_SECRET`, DB 비밀번호)은 환경변수/시크릿 매니저로만** 주입한다. 레포의 더미 시크릿은 로컬 전용이다(운영에서 반드시 교체).
- API base path 는 `/api/v0`. OpenAPI/Swagger UI 는 `springdoc-openapi-starter-webflux-ui` 로 제공.

## 7. 도메인 한눈에

- **library**: 도서 SKU/인벤토리(`book`), 대출/연체(`loan`), 예약(`reservation`), 평점·리뷰(`review`), 실시간/핫 랭킹(`RankingUseCase`/`RankingService`).
- **place**: 회의실 예약 — 건물/방/자원/예약/대시보드 (현재 `hamster-api` 의 `place/api`(컨트롤러·DTO) 중심, 코어 확장 예정).
- **jira**: 프론트 전용 데모(이슈/컴포넌트/로드맵) — 백엔드 도메인 아님.
